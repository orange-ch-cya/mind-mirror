# 第十四章 测试策略

## 14.1 测试分层

**单元测试**：覆盖所有业务逻辑层（services 目录下的引擎和服务）。计分引擎测试覆盖各种计分场景（正常计分、反向计分、多维度计分）。规则引擎测试覆盖各种条件组合和边界情况。邀请码生成测试覆盖唯一性和格式正确性。

**集成测试**：覆盖核心 API 端点的完整请求-响应流程。患者端完整流程测试（从验证邀请码到提交测评）。医生端报告生成流程测试。管理端量表 CRUD 流程测试。

**端到端测试（可选，迭代 1 后期）**：使用 Playwright 或 Cypress 模拟真实用户操作，覆盖核心用户旅程。

**安全测试**：权限校验测试（确保医生 A 无法访问医生 B 的数据）。输入注入测试（SQL 注入、XSS 攻击向量）。认证绕过测试。敏感信息泄露测试（确保错误响应不暴露内部信息）。

## 14.2 测试数据管理

使用测试专用数据库，不与生产数据库共用。测试数据使用 fixture 或 factory 模式生成，确保测试的可重复性。敏感测试场景（如撤回后数据删除验证）使用独立的事务，测试后自动回滚。
