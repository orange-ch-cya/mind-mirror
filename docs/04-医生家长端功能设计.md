# 第四章 医生/家长端功能详细设计

## 4.1 账号体系与登录验证

医生/家长端的用户是平台的核心服务对象之一。他们通过查看测评数据，在线下为患者提供专业解读。

**账号创建方式**：账号由平台管理员在管理后台手动创建，不开放自主注册。这样设计的原因是：平台的数据涉及敏感的心理健康信息，需要管理员对使用者身份进行基本把控。创建账号时需要填写：登录用户名、初始密码（首次登录强制修改）、使用者姓名或机构名称（可选）、账号角色（医生/家长/其他）、账号状态（启用/停用）。

**登录页面设计**：登录页面极简设计。包含用户名输入框、密码输入框、登录按钮、以及「忘记密码」链接（触发管理员重置密码的工作流）。页面无注册入口。背景色采用专业沉稳的色调，区别于患者端的温暖色调，暗示这是专业人士的工作区。

**登录验证逻辑**：

- 用户提交用户名和密码后，后端进行验证。
- 密码使用 bcrypt 或 argon2 算法进行哈希存储和比对，严禁明文存储。
- 连续 5 次登录失败后，该账号锁定 30 分钟，防止暴力破解。
- 登录成功后，后端生成 JWT（JSON Web Token），包含用户 ID、角色、过期时间（建议 24 小时），返回给前端。
- 前端将 JWT 存储在 localStorage 或 httpOnly cookie 中（安全起见推荐 httpOnly cookie + CSRF token 方案），后续所有 API 请求在 Authorization 头中携带该 token。

**会话管理**：

- JWT 过期后需要重新登录。
- 支持主动登出，登出时前端清除 token。
- 单账号单设备登录（可选，初期可放宽为多设备登录以方便使用）。

**首次登录强制修改密码**：创建账号时设置的初始密码为临时密码。用户首次登录时，系统检测密码是否为初始状态（可以通过密码最后修改时间字段判断，初始创建时该字段为 NULL），如果是则跳转到修改密码页面，强制修改密码后才能进入系统。新密码要求：长度不少于 8 位，包含字母和数字。

## 4.2 邀请码管理系统

邀请码是连接患者数据与医生/家长权限的唯一凭证，其管理是医生端最核心的功能。

**邀请码生成**：

- 医生登录后在「邀请码管理」页面点击「生成邀请码」按钮。
- 系统即时生成一个唯一的邀请码。邀请码格式建议：8 位字母数字混合，排除容易混淆的字符（0/O、1/I/L），保证大小写不敏感（统一存储为大写或小写）。例如：A3B7K9M2。
- 邀请码生成后立即显示在页面上，并提供「复制」按钮。同时可以生成一个包含邀请码链接的二维码，方便患者扫码直接进入答题页面（二维码编码的 URL 为：https://平台域名/patient?code=A3B7K9M2）。
- 邀请码生成时记录：邀请码内容、生成医生 ID、生成时间、状态（初始为「未使用」）、备注（可选，医生可以填写此码对应的患者称呼或用途，如「周三门诊张同学」。注意：此处填写的信息不应包含患者真实全名，系统需要提示医生注意隐私保护，或者将此字段限制为非必填且做脱敏提醒）。

**邀请码列表与状态管理**：

- 邀请码管理页面以列表形式展示当前登录医生生成的所有邀请码。
- 列表字段：邀请码、生成时间、状态、备注、操作。
- 状态标识使用不同颜色区分：
  - 未使用（灰色或蓝色）：邀请码已生成，患者尚未使用。
  - 已填（橙色）：患者已完成测评，医生尚未查看报告。
  - 已阅（绿色）：医生已查看过报告。
  - 已撤回（红色）：患者在 24 小时内撤回了数据。
  - 已过期（如果实现了有效期功能，灰色）：邀请码超过有效期未被使用。
- 操作按钮根据状态动态显示：
  - 未使用：查看二维码、复制链接、作废（手动作废邀请码）、编辑备注。
  - 已填：查看报告。
  - 已阅：查看报告。
  - 已撤回：查看撤回记录（仅能看到撤回时间和状态，看不到原始数据）。
- 支持按状态筛选和按生成时间排序。

**邀请码唯一性与安全性**：

- 邀请码在系统全局唯一，不同医生生成的邀请码不会重复。
- 邀请码仅限生成该码的医生查看其关联的数据。其他医生即使知道邀请码内容，也无法在系统中查看不属于他们的数据（权限校验在后端严格实施）。
- 邀请码生成算法需要保证足够的随机性（使用密码学安全的随机数生成器），避免被推测或枚举。

**邀请码链接跳转逻辑**：

- 患者扫描二维码或点击链接后，跳转到患者端首页，URL 参数中的邀请码自动填充到输入框中。
- 如果邀请码已过期或无效（已使用、已撤回、不存在），首页显示友好提示：「该邀请码无效或已使用，请联系向您提供邀请码的人士获取新的邀请码。」

## 4.3 报告查看功能

报告查看是医生/家长端价值实现的核心环节。报告需要在「专业详尽」和「家长可理解」之间取得平衡。

**报告入口**：从邀请码列表的「查看报告」按钮进入，或从「报告列表」统一入口查看所有已填和已阅的报告。

**报告页面整体布局**：采用左右分栏或上下分区的响应式布局（PC 端左右分栏，移动端上下堆叠）。左侧/上方为导航区，列出报告中包含的量表名称，点击可快速跳转到对应量表的详细内容。右侧/下方为主内容区，滚动展示完整报告。

**报告内容结构（从上到下）**：

**第一部分：报告概览**

- 邀请码和备注信息（医生自己填写的备注）。
- 测评完成时间。
- 知情同意状态：患者是否勾选了知情同意书，勾选时间。
- 使用的量表组合包名称（如「焦虑深度包」）。
- 一个总览表格，列出所有施测量表的名称、原始总分、常模参考范围简表。

**第二部分：逐量表详细报告**

每个量表独立一个区块，包含以下子内容：

- 量表名称（中文全称+英文缩写，如「广泛性焦虑障碍量表 GAD-7」）。
- 量表简介：一段简短的说明文字，介绍该量表测量什么、有多少题、评分范围、以及权威来源。这段简介对非专业用户（家长）非常有帮助，让他们理解接下来看到的数字意味着什么。
- 逐题作答记录：以表格形式展示，列为「题号、题目内容、患者选择、对应分数」。患者选择的文字高亮显示。这个表格让专业人士可以逐题审视患者的作答模式，发现需要线下深入讨论的具体问题。
- 维度得分（如适用）：如果量表包含多个维度，展示各维度得分及与常模的对比。例如 HADS 包含焦虑和抑郁两个分量表，SCL-90 包含 10 个因子，PSQI 包含 7 个成分。每个维度分数以进度条或仪表盘形式可视化呈现，同时标注常模参考范围。
- 总分与常模对比：显著展示该量表的总分，并附上与常模数据的对比。常模对比可以设计为：显示患者分数在常模分布中所处的位置（如「高于 80% 的同龄人群」「处于中等偏高水平」），同时显示常模的分级参考（如正常/轻度/中度/重度阈值）。所有对比表述使用描述性语言，避免「异常」「不正常」等标签化表述，改为「偏高范围」「需要关注的水平」等。
- 分科参考标签：如果该量表的分数匹配了分科规则，显示对应的分科标签。标签分为「医生版简短描述」和「家长版详细描述」，根据当前登录用户的角色优先显示对应版本（医生账号看简短版，家长账号看详细版）。两个版本都存储在数据库中，管理员可以切换查看。标签样式设计为带图标的提示卡片，而非警示弹窗，传达「建议参考」而非「判定结论」的语意。

**第三部分：综合分科参考**

如果患者完成了多个量表，系统根据各量表得分的组合情况，生成一个综合性的分科参考建议。这个综合建议由硬规则引擎根据预先配置的规则组合生成。例如：「GAD-7 中度 + PHQ-9 中度 + PSQI 睡眠质量差」的组合可能触发「建议综合评估情绪与睡眠问题」的综合标签。综合建议展示在报告最后，以汇总卡片形式呈现。

**第四部分：报告尾部固定信息**

- 免责声明（硬编码，与患者端一致）：「本报告基于患者自评量表数据生成，仅反映患者作答期间的主观感受，不代表临床诊断。量表的任何分数或分科建议仅供专业人士参考，请结合临床面诊进行综合判断。」
- 报告生成时间戳。
- 平台版权信息。

**报告查看后的状态更新**：医生首次打开某份报告时，对应邀请码的状态自动从「已填」更新为「已阅」。这个状态更新用于帮助医生追踪哪些报告已经处理过。更新是自动的（打开即标记），不需要手动点击「标记已阅」按钮，减少操作步骤。

## 4.4 数据导出功能

医生需要能够将报告导出为可离线阅读或打印的格式，用于存档或线下讨论。

**导出格式支持**：

- PDF 导出：适合打印和正式存档。排版精美，带有平台 Logo 和报告标题。
- Excel 导出：适合数据分析。包含原始数据格式，每个量表的每题得分、维度得分、总分，以结构化表格形式呈现，方便医生进行进一步的数据处理或图表制作。

**PDF 导出设计**：

- 封面页：包含平台 Logo、报告标题（「心理状态自测报告」）、邀请码备注（如有）、测评日期、导出日期、生成机构信息。
- 内容页：按照报告查看的相同结构呈现，保持与在线报告一致的排版和层级。
- 页脚：每页页脚显示免责声明摘要和页码。
- 导出按钮：在报告查看页面的顶部或底部提供「导出 PDF」和「导出 Excel」按钮。点击后后端生成文件并触发下载。文件生成可能需要几秒钟，期间显示加载状态。

**Excel 导出设计**：

- 第一个工作表「概览」：包含患者的基本测评信息（邀请码、测评时间、各量表名称和总分）。
- 后续每个量表独立一个工作表：工作表名称为量表缩写（如 GAD-7）。每个工作表包含：题号、题目完整文本、患者得分、可选范围、常模参考值（如有）。
- 最后一个工作表「原始数据」：以规范化的数据格式列出所有数据，每行一条作答记录，字段包括：量表名称、题号、题目文本、患者得分、维度归属（如适用）。

**导出权限与安全**：导出操作仅限该数据归属的医生账号执行。后端需要在导出接口中进行权限校验。导出的文件不在服务器端留存，生成后即时返回客户端并删除临时文件。文件不包含患者个人身份信息（因为系统本身就不采集）。

## 4.5 知情记录查看

每一次知情同意的勾选都是重要的追溯凭证。医生端需要能够查看这些记录。

**知情记录入口**：在报告详情页的「报告概览」区域，醒目位置显示「知情同意状态：已签署（签署时间：YYYY-MM-DD HH:MM:SS）」。点击该状态文字可展开查看知情同意书的完整文本内容，以及签署时的相关信息（时间戳、用户代理摘要）。

**知情记录的法律意义**：该记录证明患者在答题前已被明确告知数据的去向和使用方式，且主动选择了同意。在出现数据隐私相关争议时，这份记录是平台和医生的重要保护。系统需要确保这些记录不可篡改、不可删除（除了随患者 24 小时撤回而删除）。
