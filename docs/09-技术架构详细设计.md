# 第九章 技术架构详细设计

## 9.1 技术选型说明

**后端框架：Python Flask**

选择理由：轻量级、灵活、学习曲线平缓，极其适合单人开发和快速迭代。Flask 的扩展生态可以按需添加功能（如 Flask-SQLAlchemy 用于数据库 ORM、Flask-JWT 用于认证、Flask-CORS 用于跨域支持），不会像 Django 那样携带大量初期不需要的功能。Python 生态在数据处理方面有明显优势（计分引擎、规则引擎的实现会更简洁）。

**数据库：SQLite（初期）/ PostgreSQL（后续）**

选择理由：SQLite 零配置、零运维，文件型数据库直接存储在笔记本硬盘上，非常适合单机部署场景。Flask-SQLAlchemy 作为 ORM 层可以无缝切换数据库后端，当需要迁移到 PostgreSQL 时，只需修改数据库连接字符串，几乎不需要改动业务代码。SQLite 的并发能力对于初期用户量（医生数量在几十人以内、患者测评请求稀疏）完全够用。

**前端-患者端：原生 HTML/CSS/JavaScript + 轻量级 UI 框架**

选择理由：患者端功能相对简单（表单填写+结果展示），使用原生技术或极轻量框架（如 Alpine.js + Tailwind CSS）可以做到极小的打包体积和快速的加载速度。这对于移动端网络环境不稳定的场景非常重要。不使用 React/Vue 等重型框架，保持页面简洁和性能优秀。

**前端-医生端/管理端：React 或 Vue + 组件库**

选择理由：医生端和管理端有较为复杂的交互（邀请码管理表格、报告富文本展示、量表编辑器、规则配置器等），使用现代前端框架可以显著提升开发效率和用户体验。组件库推荐使用 Ant Design（React）或 Element Plus（Vue），提供了表格、表单、弹窗等后台管理常用组件。医生端需要响应式设计以支持手机查看报告。

**部署方案：笔记本 + DDNS + Nginx 反向代理**

选择理由：最低成本的部署方案。使用一台 7×24 小时开机的笔记本电脑（建议配置：8GB 以上内存、SSD 硬盘、稳定供电），安装 Linux 系统（Ubuntu Server LTS 推荐）。通过 DDNS 服务（如花生壳、Cloudflare DDNS）将动态 IP 映射到固定域名。使用 Nginx 作为反向代理和静态文件服务器，Gunicorn 或 uWSGI 作为 Flask 应用的 WSGI 服务器。HTTPS 通过 Let's Encrypt 的 certbot 自动管理。这个方案的总成本：域名费（约 50 元/年）+ 电费（约 100-200 元/年）+ DDNS 服务费（可能有，约 100-200 元/年）。全年运营成本可控制在 500 元以内。

## 9.3 数据库核心表结构设计

以下是核心业务表的简化 DDL 设计（SQLite 语法，迁移到 PostgreSQL 时仅需微调）：

**医生/管理员用户表 (users)**：

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    display_name VARCHAR(100),
    role VARCHAR(20) NOT NULL DEFAULT 'doctor',  -- 'doctor', 'parent', 'admin'
    status VARCHAR(20) NOT NULL DEFAULT 'active',  -- 'active', 'disabled'
    must_change_password BOOLEAN DEFAULT 1,
    last_login_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**邀请码表 (invite_codes)**：

```sql
CREATE TABLE invite_codes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code VARCHAR(8) UNIQUE NOT NULL,
    creator_id INTEGER NOT NULL REFERENCES users(id),
    status VARCHAR(20) NOT NULL DEFAULT 'unused',
    -- 'unused', 'used', 'viewed', 'revoked', 'expired', 'cancelled'
    remark VARCHAR(200),
    generated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    used_at DATETIME,
    viewed_at DATETIME,
    revoked_at DATETIME,
    expired_at DATETIME
);
CREATE INDEX idx_invite_codes_creator ON invite_codes(creator_id);
CREATE INDEX idx_invite_codes_status ON invite_codes(status);
```

**测评会话表 (assessment_sessions)**：

```sql
CREATE TABLE assessment_sessions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    invite_code_id INTEGER UNIQUE NOT NULL REFERENCES invite_codes(id),
    status VARCHAR(20) NOT NULL DEFAULT 'in_progress',
    -- 'in_progress', 'completed', 'revoked'
    push_package_id INTEGER REFERENCES scale_packages(id),
    consent_given BOOLEAN NOT NULL DEFAULT 0,
    consent_at DATETIME,
    consent_ua_hash VARCHAR(64),  -- 用户代理的哈希值
    started_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    completed_at DATETIME,
    revoked_at DATETIME,
    user_agent_hash VARCHAR(64)
);
```

**作答记录表 (item_responses)**：

```sql
CREATE TABLE item_responses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL REFERENCES assessment_sessions(id),
    scale_id INTEGER NOT NULL REFERENCES scales(id),
    item_number INTEGER NOT NULL,
    item_text TEXT NOT NULL,
    raw_score INTEGER NOT NULL,   -- 原始选项分数
    final_score INTEGER NOT NULL,  -- 反向计分处理后的得分
    reversed BOOLEAN DEFAULT 0,
    dimension VARCHAR(50),
    responded_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_item_responses_session ON item_responses(session_id);
```

**量表配置表 (scales)**：

```sql
CREATE TABLE scales (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name_zh VARCHAR(100) NOT NULL,
    name_en VARCHAR(50),
    abbreviation VARCHAR(20),
    source TEXT,
    description TEXT,
    target_population VARCHAR(100),  -- 逗号分隔标签
    estimated_minutes INTEGER,
    status VARCHAR(20) DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**量表条目表 (scale_items)**：

```sql
CREATE TABLE scale_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    scale_id INTEGER NOT NULL REFERENCES scales(id) ON DELETE CASCADE,
    item_number INTEGER NOT NULL,
    item_text TEXT NOT NULL,
    options_json TEXT NOT NULL,  -- JSON: [{"text":"完全没有","score":0},...]
    is_reversed BOOLEAN DEFAULT 0,
    dimension VARCHAR(50),
    sort_order INTEGER DEFAULT 0
);
CREATE INDEX idx_scale_items_scale ON scale_items(scale_id);
```

**常模数据表 (norms)**：

```sql
CREATE TABLE norms (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    scale_id INTEGER NOT NULL REFERENCES scales(id),
    dimension VARCHAR(50) NOT NULL DEFAULT 'total',
    population_group VARCHAR(100),  -- 如 "18-25岁男性"
    sample_size INTEGER,
    source TEXT,
    mean REAL,
    std_dev REAL,
    percentiles_json TEXT,  -- JSON: {"p25":5,"p50":8,"p75":12,...}
    thresholds_json TEXT,   -- JSON: {"mild":5,"moderate":10,"severe":15}
    status VARCHAR(20) DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**分科规则表 (referral_rules)**：

```sql
CREATE TABLE referral_rules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL,
    priority INTEGER DEFAULT 100,
    condition_json TEXT NOT NULL,
    output_label_doctor TEXT NOT NULL,
    output_label_parent TEXT,
    output_style VARCHAR(20) DEFAULT 'info',  -- 'info','warning','alert'
    output_tags VARCHAR(200),  -- 逗号分隔的场景标签
    status VARCHAR(20) DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**操作日志表 (audit_logs)**：

```sql
CREATE TABLE audit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER REFERENCES users(id),
    action VARCHAR(50) NOT NULL,
    target_type VARCHAR(50),
    target_id INTEGER,
    detail TEXT,
    ip_hash VARCHAR(64),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 9.4 API 接口设计概览

以下列出所有核心 API 端点，详细请求/响应格式在独立 API 文档中定义。

**患者端接口（无需认证）**：

- POST /api/v1/patient/verify-code - 验证邀请码有效性
- POST /api/v1/patient/consent - 提交知情同意
- POST /api/v1/patient/phq4-submit - 提交 PHQ-4 快筛答案，返回推送的组合包
- POST /api/v1/patient/response - 提交单题作答（暂存）
- POST /api/v1/patient/submit - 提交全部作答，完成测评
- GET /api/v1/patient/result/{session_id} - 获取患者版结果页数据
- POST /api/v1/patient/revoke/{session_id} - 撤回数据
- GET /api/v1/patient/session-status/{invite_code} - 查询邀请码对应的会话状态（用于断点续答）

**医生端接口（需认证）**：

- POST /api/v1/auth/login - 登录
- POST /api/v1/auth/logout - 登出
- POST /api/v1/auth/change-password - 修改密码
- POST /api/v1/doctor/invite-codes - 生成邀请码
- GET /api/v1/doctor/invite-codes - 获取邀请码列表（支持筛选和分页）
- PATCH /api/v1/doctor/invite-codes/{id} - 更新邀请码（作废、修改备注）
- GET /api/v1/doctor/reports - 获取报告列表
- GET /api/v1/doctor/reports/{session_id} - 获取完整报告详情
- GET /api/v1/doctor/reports/{session_id}/export/pdf - 导出 PDF
- GET /api/v1/doctor/reports/{session_id}/export/excel - 导出 Excel

**管理端接口（需管理员认证）**：

- GET /api/v1/admin/scales - 量表列表
- POST /api/v1/admin/scales - 新增量表
- PUT /api/v1/admin/scales/{id} - 编辑量表
- DELETE /api/v1/admin/scales/{id} - 删除量表
- GET /api/v1/admin/scales/{id}/items - 获取量表条目
- POST /api/v1/admin/scales/{id}/items - 添加条目
- PUT /api/v1/admin/scales/{id}/items/{item_id} - 编辑条目
- DELETE /api/v1/admin/scales/{id}/items/{item_id} - 删除条目
- GET /api/v1/admin/norms - 常模列表
- POST /api/v1/admin/norms - 新增常模
- POST /api/v1/admin/norms/import - 批量导入常模
- GET /api/v1/admin/rules - 分科规则列表
- POST /api/v1/admin/rules - 新增规则
- PUT /api/v1/admin/rules/{id} - 编辑规则
- GET /api/v1/admin/users - 医生账号列表
- POST /api/v1/admin/users - 创建医生账号
- PUT /api/v1/admin/users/{id} - 编辑医生账号
- POST /api/v1/admin/users/{id}/reset-password - 重置密码
- GET /api/v1/admin/configs - 获取系统配置
- PUT /api/v1/admin/configs - 更新系统配置
- GET /api/v1/admin/logs - 查看操作日志
